# AeroE Checklist – native apps (iOS and Android)

This folder wraps the web app in the parent folder into store-ready iOS and Android apps with
[Capacitor](https://capacitorjs.com). Nothing is rewritten: `build-web.js` copies the web app into `www/`,
turns off the service worker (the shell bundles everything), and bundles the offline speech engine so
there is no download step. The native projects in `ios/` and `android/` are committed; the copied web
files are not (they are regenerated by every sync).

## What you need on the Mac

- macOS with **Xcode** (App Store) and the command line tools (`xcode-select --install`)
- **CocoaPods** (`sudo gem install cocoapods` or `brew install cocoapods`)
- **Node.js 20+** (`brew install node`)
- An **Apple Developer Program** membership for the company, and the company's App Store Connect access
- For Android: **Android Studio** with an SDK installed

## Build and run on a connected iPad

```bash
git clone https://github.com/swalksa350/AeroE-checklist.git
cd AeroE-checklist/native
npm install
npm run assets          # generates app icons and splash screens from resources/ (first time, and after icon changes)
npm run ios             # builds www/, syncs it into the Xcode project and opens Xcode
```

In Xcode: select the `App` target → *Signing & Capabilities* → choose the company team (Xcode creates the
provisioning profile). Plug in the iPad, pick it as the run destination, press Run. The first run asks the
iPad to trust the developer certificate (Settings → General → VPN & Device Management).

Every time the web app changes, run `npm run sync` (or `npm run ios`) and build again in Xcode.

## Android

```bash
npm run android         # syncs and opens Android Studio; Run on a connected device or emulator
```

## TestFlight and the App Store

1. In Xcode choose *Product → Archive*, then *Distribute App → App Store Connect → Upload*.
2. In App Store Connect create the app record (bundle id `au.com.aeroe.checklist`, name "AeroE Checklist",
   primary category Navigation or Utilities; the review notes should say the app works offline and that the
   microphone is used only for on-device recognition of checklist commands).
3. Add internal testers under TestFlight; external testers need a short beta review.
4. For the public release: screenshots (iPad 13" and 11", iPhone 6.7"), privacy policy URL, support URL,
   the App Privacy questionnaire (no data collected: everything stays on the device), age rating, price.

## Versioning

- The marketing version is `MARKETING_VERSION` in `ios/App/App.xcodeproj/project.pbxproj` and
  `versionName` in `android/app/build.gradle` (currently 2.1.0). Bump both with each store release and
  raise the build number (`CURRENT_PROJECT_VERSION` / `versionCode`) on every upload.
- The web app's own version (`changes.json`) is shown on the Status page and should match.
